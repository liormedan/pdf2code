# מפת המערכת — כלי מפתחים

> **זה אינו חלק ממוצר pdf2code.** לא לשונית, לא מסך, ולא פיצ׳ר של לקוח. אין מהאפליקציה שום נתיב ניווט לכאן, ו-Three.js אינה תלות של המוצר.

המפה מראה מה התוכנה עשויה ממנו ואיפה היא עומדת: שלושת התהליכים, מה כל אחד עושה ומה אסור לו, אילו יכולות קיימות, ומצב הספרינטים, החסמים וההכרעות.

**היא נוצרת, לא מצוירת.** תרשים שמתוחזק ביד הופך למקום שני שבו מצב חי, והמקום השני תמיד מתיישן — בעוד שהוא זה שאנשים מסתכלים עליו, כי הוא היפה.

---

## למה זה יושב כאן ולא באפליקציה

זה **היה** לשונית רביעית בתוך pdf2code, ליום אחד. הטעות הייתה ברורה בצורתה: היא הכניסה **ספריית תלת-ממד של 560KB**, עשרים ושתיים מחרוזות מפתחים, ולוח מצב פנימי — **לתוך מתקין שלקוח משלם עליו וצוות אבטחה בודק.** אף אחד משלושת הדברים אינו תכונה של ממיר PDF.

המפה שווה את קיומה, ושווה שתהיה **כאן** — אצל מי שקורא אותה.

**התלות מצביעה לכיוון אחד בלבד.** שום קובץ תחת `desktop/app/` אינו מייבא דבר מכאן; ה-viewer קורא את `../system-map.json` ואת קובץ הטוקנים של האפליקציה, שניהם לקריאה בלבד. זו הסיבה ש״לא נארז״ היא עובדה על הבנייה ולא הערה במסמך.

---

## 1. לסנכרן את הנתונים

```bash
cd desktop/visualization && npm run map:sync      # אחרי שינוי במסמכים
cd desktop/visualization && npm run map:check     # מה שה-CI מריץ
```

**אין תלויות להתקין** — הגנרטור הוא Node על חמישה קובצי Markdown.

`map:check` רץ ב-CI כ-**job נפרד** ב-[desktop.yml](../../.github/workflows/desktop.yml), ולא בתוך `npm run check` של האפליקציה. אדום שם אומר שהמסמכים זזו והמפה לא — **וזו אינה סיבה לפקפק במתקינים**, ולכן `installers` לא תלוי בו.

**אין git hook.** הפקודה גלויה, והדיף של `system-map.json` נקרא לפני שהוא מקומט: מפה שזזה מעצמה שווה מבט.

## 2. לפתוח את ה-viewer

```bash
cd desktop/visualization/viewer && npm install    # פעם אחת
cd desktop/visualization/viewer && npm run dev
```

נפתח על `http://localhost:5180`.

**כן, זה שרת פיתוח מקומי — ורק בזמן פיתוח.** הוא רץ על המכונה של המפתח, בפקודה מפורשת, ונסגר עם הטרמינל. **למוצר המותקן אין פורט מאזין בכלל**: pdf2code מדבר עם המנוע ב-NDJSON על stdin/stdout, וזו הכרעה מ-5.9.2026 שנרשמה ב-[decisions.md](../decisions.md) בדיוק כי פורט מאזין הוא ממצא בסריקת אבטחה אצל הלקוח המרכזי. ה-viewer אינו נארז, אינו ב-MSI וב-NSIS, ואינו רץ אצל אף לקוח.

**5180 ולא 1420 בכוונה.** 1420 שייך לשרת הפיתוח של האפליקציה עם `strictPort`, וכלי שיכול לתפוס את הפורט של המוצר הוא כלי ששובר את ההרצה שלו. גם כאן `strictPort` — אם 5180 תפוס הוא יגיד, ולא יזוז בשקט.

## שני חצאים, ורק אחד מהם נכתב ביד

| קובץ | מי כותב | מה יש בו |
| --- | --- | --- |
| `system-map.json` | **הסקריפט** | ספרינטים, חסמים, הכרעות, התקדמות. **לא לערוך** — ייכתב מחדש |
| `system-map.authored.json` | **אדם** | מה כל תהליך *הוא*, מה הוא *אינו*, אילו קבצים שלו, ומה אסור. **בלי שום סטטוס** |
| `sync-system-map.mjs` | — | קורא את חמשת המסמכים, מאמת, ומרכיב את השניים |
| `viewer/` | — | ה-viewer. `package.json` משלו, תלויות משלו, ובהן Three.js |

**החלוקה אינה שרירותית.** לסקריפט מותר לקרוא *מבנה* — כותרות, טבלאות, תיבות סימון — כי אלה עובדות. משפט אינו עובדה שאפשר לפרסר, וסקריפט שהיה מסיק ״הספרינט הזה נשמע גמור״ מפסקה היה ממציא בדיוק את מה שהמפה קיימת כדי למנוע. לכן התיאורים בקובץ שאדם כתב — **והסקריפט מאמת אותו** ולא סומך עליו: כל מזהה חייב להופיע בקשרים, כל קשר חייב לנקוב במזהים קיימים, וכל טענה חייבת לצטט מסמך שהוא באמת אחד מהמקורות.

**חמשת המקורות:** `delegation.md` · `architecture.md` · `backlog.md` · `built.md` · `decisions.md`

## מה הסקריפט מסרב לעשות

הוא **נכשל ולא מנחש**, וכל בדיקה נכתבה כי שני מסמכים באמת סתרו זה את זה או יכלו:

- ספרינט שחסום על מזהה שאינו בטבלת החסמים
- ספרינט מסומן ✅ ש-`delegation.md` §7 עדיין מציג כממתין לך
- ספרינט מסומן ✅ שנשארו בו פריטים לא מסומנים שאינם ״נדחתה״ או ״עבר לספרינט״
- הכרעה פתוחה שחוסמת ספרינט שאינו קיים, או שכבר נסגר
- משקלים שאינם מסתכמים ל-100%
- ספרינט בטווח ״קטגוריה ג״ ש-§2 מגדיר, ושהכותרת שלו ב-backlog לא אומרת **שלך**
- האחוז ש-§14 מצהיר עליו, מול סכום המשקלים בפועל
- **אותו מזהה חסם בשני קבצים במשמעויות שונות** — מצב אמיתי בין `backlog.md` ל-`built.md`, ולכן built.md חייב להצהיר שהמספור שלו הוא זה שלפני 6.9

> **מפה שחסרה עולה דקה. מפה שבטוחה בעצמה וטועה עולה החלטה.**

## נגישות, וההכרעה שמאחוריה

**הרשימה היא הממשק, והתמונה היא האיור.** כל תהליך, מודול, ספרינט והכרעה בקנבס קיימים גם כ-DOM אמיתי לצדו — כפתורים שמגיעים אליהם ב-Tab, שקורא מסך קורא, ושמתורגמים לשתי השפות.

**הקנבס עצמו `aria-hidden`.** קנבס אינו יכול להיות אף אחד מהדברים האלה, ו-ARIA עליו רק *טוען* שהוא כן. הבחירה משותפת לשניהם — לחיצה על תיבה בסצנה ו-Enter על שורה ברשימה עושים אותו דבר.

**אין טקסט בתוך התלת-ממד.** התוויות הן DOM שמוצב מעל הקנבס לפי הקרנה — כך הן נשארות ניתנות לבחירה, מתורגמות, ונכונות ב-RTL, בלי לשלוח אטלס גופנים כדי לצייר שש מילים. זו גם הדרך היחידה שהעברית יוצאת נכונה.

**`prefers-reduced-motion` מכובד וגם נצפה תוך כדי ריצה.** הדבר היחיד שזז הוא החרוזים שנעים בצינורות, והם נושאים משמעות: זה הכיוון שבו נתונים באמת עוברים. בתנועה מופחתת הם עומדים ומסמנים את הצינור.

**צבע לעולם אינו האות היחיד**, וארבעת המצבים לוקחים את הטוקנים של המוצר — שה-`check-a11y` שלו כבר מודד בשני מצבי הצבע. ה-viewer מייבא את `app/src/index.css` במקום להעתיק אותו, ולכן הצבעים כאן הם אותם צבעים ותחת אותה בדיקה.

**הסטנדרט הזה לא התרופף כשזה הפסיק להיות פיצ׳ר.** כלי שהצוות קורא כל יום הוא המקום הלא נכון להתחיל בו חריגים.

## תלות

**Three.js 0.186.0, רישיון MIT** — יושבת ב-`viewer/package.json` **בלבד**. היא אינה ב-`desktop/app/package.json`, אינה ב-lockfile שלו, ואינה במסך ״אודות״ של המוצר, כי היא אינה נארזת אליו. `OrbitControls` מגיע מתוך החבילה עצמה; אין `react-three-fiber` ואין ספריית עזר.

**אין רשת, telemetry, העלאה או שירות חיצוני** — לא כאן ולא במוצר. ה-viewer קורא קובץ JSON מקומי, ותו לא.

## מה המפה במכוון אינה

**אינה מדד.** גובה תיבה אינו מספר שורות ואינו מורכבות — כל התיבות באותו גובה, כדי שאיש לא יקרא בהן מה שלא נאמר.

**אינה מכילה נתוני משתמש.** אין בה נתיב, אין שם קובץ ואין תוכן מסמך — היא מתארת את התוכנה, לא את מה שמישהו המיר בה. זה נובע מעצם הבנייה: המקורות היחידים שלה הם חמישה מסמכי תכנון בריפו.

# ארכיטקטורה — Tauri · React · מנוע פייתון

מסמך טכני. הוא מניח את [spec.md](spec.md) כקרוא, ועונה על שאלה אחת: **איך שלושת החלקים מדברים, ומה נשבר אם עושים את זה לא נכון.**

---

## 1. שלושה תהליכים, ולמה בדיוק שלושה

```
┌──────────────────────────────────────────────┐
│  Tauri shell  (Rust)                         │
│  חלון · תפריטים · דיאלוג קבצים · עדכונים     │
│  · רישיון · והשומר היחיד של מסלול הקבצים     │
│                                              │
│  ┌────────────────┐      ┌────────────────┐  │
│  │  WebView       │      │  Python sidecar│  │
│  │  React+shadcn  │◄────►│  מנוע ההמרה    │  │
│  │  ממשק בלבד     │ IPC  │  pdfium+miner  │  │
│  └────────────────┘      └────────────────┘  │
└──────────────────────────────────────────────┘
```

**למה WebView ולא ממשק נייטיב:** כי `components/`, `messages/` ו-RTL כבר קיימים ועובדים. ממשק נייטיב היה זורק אותם ומתחיל מאפס בעברית — שהיא בדיוק המקום שבו ערכות נייטיב הכי חלשות.

**למה פייתון בתהליך נפרד ולא מוטמע ב-Rust:** המרה של 800 עמודים היא עבודה ארוכה שיכולה ליפול. תהליך נפרד אפשר להרוג, להגביל בזיכרון, ולהפעיל מחדש בלי להפיל את החלון. גם: קריסה בספריית C שמאחורי PDF לא לוקחת איתה את האפליקציה.

**מה ה-WebView לא עושה, לעולם:** לא ניגש לקבצים ולא מריץ המרות. הוא מקבל נתיבים ומחזיר פקודות. כל מגע בדיסק עובר דרך Rust. זה לא סגנון — זה מה שמונע מדף שנטען בתוך התצוגה המקדימה להגיע למערכת הקבצים.

## 2. חוזה ה-IPC

**stdio, לא HTTP.** JSON תחום שורות על `stdin`/`stdout` של הסיידקאר.

הסיבה עסקית ולא אסתטית: הלקוח המרכזי שלנו (מצב 6 — מסמך שאסור להעלות) עובר לעיתים ביקורת אבטחה. שרת HTTP מקומי, גם על `127.0.0.1` וגם עם טוקן, הוא פורט פתוח שסורק ימצא, ש-EDR ידווח עליו, ושיצטרך הסבר. stdio לא מייצר שום דבר להסביר: אין סוקט, אין פורט, והתהליך מת עם ההורה.

### הודעות

בקשה מ-Rust לפייתון:

```json
{"id":"7c1","op":"convert","args":{
  "path":"C:/docs/report.pdf",
  "formats":["html","react"],
  "background":true,"backgroundScale":2,
  "maxPages":0,"out":"C:/out/report"
}}
```

תשובות — אפס או יותר `progress`, ואז בדיוק אחת מ-`result` / `error`:

```json
{"id":"7c1","type":"progress","page":12,"pages":150,"phase":"extract"}
{"id":"7c1","type":"result","info":{...},"files":["index.html"],"warnings":[...]}
{"id":"7c1","type":"error","code":"ENCRYPTED","message":"..."}
```

`phase`, `WarningCode` ומבנה `info` **מועתקים מ-[types.ts](../src/converter/types.ts) ולא מומצאים מחדש** — הממשק כבר יודע להציג אותם, והמחרוזות המתורגמות כבר קיימות ב-`messages/`.

### שלוש נקודות שנשברות בקלות

1. **ביטול.** `{"op":"cancel","id":"7c1"}` נכנס בזמן שהמרה רצה, ולכן הסיידקאר **חייב לקרוא את `stdin` בתהליכון נפרד** מהעבודה. לולאת קריאה חוסמת בתהליכון העבודה הופכת את הביטול לתיאורטי — וזו בדיוק בדיקת QA קיימת (״ביטול הוא מיידי״).
2. **הפלט לא עובר ב-IPC.** ראסטרים של 150 עמודים דרך צינור הם עשרות מגה-בייט של base64. הפייתון **כותב לדיסק** ומחזיר נתיבים. התצוגה המקדימה קוראת דרך פרוטוקול הנכסים של Tauri.
3. **stdout הוא ערוץ הפרוטוקול.** `print` אחד ששכחו בקוד הפייתון מרעיל את הזרם. כל הלוגים ל-`stderr`, בלי יוצא מן הכלל, ו-`sys.stdout` נחסם בפועל מיד עם העלייה.

## 3. המנוע — הספריות, והשאלה המשפטית

הארכיטקטורה הדו-שכבתית מכתיבה חלוקה נקייה: **ספרייה אחת לראסטר, אחרת לטקסט.**

| תפקיד | ספרייה | רישיון (לאימות) | למה היא |
| --- | --- | --- | --- |
| שכבת ראסטר | **pypdfium2** | Apache-2.0 / BSD-3 | PDFium — אותו מנוע שמרנדר ב-Chrome, כלומר הראסטר ייראה כמו מה שהמשתמש רואה בדפדפן |
| שכבת טקסט | **pdfminer.six** | MIT | מיקום ברמת תו + שם הפונט המוטמע. זה בדיוק מה ש-`extract.ts` צריך |
| תמונות | **Pillow** | MIT-CMU | JPEG מול PNG לפי `RasterHint` — ההבחנה כבר מוכרעת בקוד הקיים |
| OCR (v1.1) | **Tesseract** | Apache-2.0 | מקומי, בלי רשת |
| PPTX (v1.1) | **LibreOffice headless** | MPL-2.0 | אותו רנדרר שהתוכנית הישנה תכננה לשרת |

### ההכרעה, והאזהרה שקדמה לה

**PyMuPDF הייתה הבחירה המתבקשת, ונדחתה.** היא עושה לבד את מה שהשתיים הראשונות עושות ביחד, מהר יותר ובפחות קוד. הרישיון שלה הוא **AGPL-3.0 או רישיון מסחרי בתשלום מ-Artifex**. במוצר דסקטופ סגור שנמכר בכסף, AGPL הוא סיכון אמיתי, והחלופה היא תשלום שנתי שאיש עוד לא תמחר.

**הוכרע ב-5.9.2026: pypdfium2 + pdfminer.six.** איטית יותר, שתי תלויות במקום אחת, **ורישיון שלא מחייב אף אחד לפתוח את הקוד או לשלם.** אם המהירות תתברר כחסם, זו הכרעה שחוזרים אליה עם מספרים — לא לפניה.

**כל שורה בטבלה טעונה אימות לפני התחייבות.** רישיונות משתנים בין גרסאות, ומסמך פנימי אינו ייעוץ משפטי.

## 4. הצד של הפרונט

- **Vite + React 19 + TypeScript.** בלי Next: אין SSR, אין ראוטר של שרת, ואין מה שיצדיק אותו.
- **shadcn/ui + Tailwind v4** — 16 הרכיבים הקיימים ב-`components/ui/` עוברים כמעט ללא שינוי.
- **i18n** — `messages/he.json` ו-`en.json` עוברים. `next-intl` מוחלף בספרייה קלה או בטעינה ידנית; **הכיווניות ממשיכה להיגזר מתת-תג השפה ולא להיות מוגדרת**, כמו היום.
- **מצב** — מצב מקומי ו-React Query מול פקודות Tauri. אין צורך במנהל מצב גלובלי לחלון אחד.
- **`invoke` לפקודות, `listen` לאירועי התקדמות.** ההתקדמות מגיעה מהפייתון, דרך Rust, כאירוע — לא כתשובה לבקשה.

**מה שהפרונט לא מייבא:** את המנוע. גם לא ״רק בשביל התצוגה המקדימה״. ברגע שהוא עושה את זה, קיימים שני מימושים ואחד מהם לא נבדק.

## 5. הרשאות ואבטחה בתוך Tauri

תוכנה שנקנית בגלל שהיא לא שולחת כלום חייבת להיות ניתנת להוכחה:

- **allowlist מינימלי.** בלי `shell.open`, בלי `http`, בלי `fs` גורף לחלון. הפרונט מקבל פקודות ייעודיות בלבד.
- **CSP קשיח** על ה-WebView, בלי `unsafe-eval`.
- **התצוגה המקדימה של הפלט מבודדת.** ה-HTML שאנחנו מייצרים נבנה מתוכן של מסמך שאיש לא בדק — הוא נטען ב-`iframe` עם `sandbox`, ולא בהקשר של האפליקציה. בדיקת ההזרקה הקיימת מגנה על הפלט; הבידוד מגן עלינו מפני מה שהיא תפספס.
- **המנוע כותב רק לאן שנבחר.** `engine_call` מעביר את מה שהחלון שם ב-`args`, וחמש מתשע הפעולות מקבלות `out` — כלומר בלי שער, פרונט שנפרץ מחזיק **פרימיטיב כתיבה בכל נתיב**, דרך מנוע שיוצר תיקיות בדרך. [workbench.rs](app/src-tauri/src/workbench.rs) מחזיק רשימת נתיבים מותרים; נתיב נכנס אליה רק מדיאלוג נייטיבי או מ-`output_dir` שיצר אותו בעצמו, והבדיקה קורית לפני שהמנוע רואה את הבקשה.
- **בלי רשת יוצאת** מהסיידקאר, ובלי טלמטריה שלא בוקשה.
- **בדיקת עדכונים היא היציאה היחידה לרשת**, היא מוצהרת בממשק, וניתן לכבותה.

## 6. אריזה והפצה

| שלב | כלי | הערה |
| --- | --- | --- |
| בניית הסיידקאר | PyInstaller (`--onedir`) | `onedir` ולא `onefile`: `onefile` פורק לתיקייה זמנית בכל הרצה, מאט את העלייה ומרגיז אנטי-וירוסים |
| הטמעה | `externalBin` של Tauri | ה-Rust מאתר את הבינארי לצידו, לא ב-`PATH` |
| התקנה | MSI / NSIS | Windows ראשון |
| חתימה | תעודת OV/EV | **בלי זה SmartScreen מציג אזהרה לכל מתקין.** במוצר שנמכר על אמון זה לא פגם קוסמטי |
| עדכונים | Tauri updater | מניפסט חתום. לוודא שהעדכון לא דורס העדפות |

**מה שהופך את זה לצפוי:** לבנות התקנה חתומה **בספרינט הראשון**, על אפליקציה שלא עושה כלום מלבד להיפתח. שתי התקלות של 19.8 בפרויקט הישן שרדו טייפצ'ק ו-70 בדיקות כי היו סביבתיות — ובאריזה, כמעט הכל סביבתי. התקלות האלה נמצאות רק על מכונה שאינה שלנו, ורק כשמנסים באמת להתקין.

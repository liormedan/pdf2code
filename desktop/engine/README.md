# pdf2code Engine

מנוע ההמרה, כתהליך נפרד. הוא ממיר: PDF נכנס, HTML עצמאי או רכיב React יוצא, והפלט **נכתב לדיסק** בעוד הצינור נושא רק שמות.

## הרצה ובדיקה

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe test_protocol.py
```

חמש סוויטות, בלי מסגרת בדיקות:

| קובץ | מה הוא מוודא |
| --- | --- |
| `test_protocol.py` | חוזה הסיידקאר — 21 בדיקות. מקבל נתיב לבינארי קפוא כארגומנט |
| `test_engine.py` | **התאמה לטייפסקריפט** — 44 פונטים, 12 שפות, וארבעה מודלי עמוד |
| `test_output.py` | **הזרקה** — הפלט מול `09-hostile-text.pdf`, וסיווגי הראסטר |
| `test_pages.py` | **הסדנה** — התוכנית, הסירובים, התמונות, וקריטריון הסיום |
| `test_archive.py` | **אריזה ל-ZIP** — ובראשן הסירוב לכתוב ארכיון בתוך התיקייה שהוא אורז |

ולידציית HTML5 והידור JSX דורשים את כלי ה-Node של המאגר, ולכן הם ב-`parity/validate_output.mjs`.

בלי מסגרת בדיקות בכוונה: המנוע נארז כבינארי עם סט התלויות הקטן ביותר שאפשר להגן עליו, ומריץ בדיקות ב-`requirements.txt` הוא תלות שמישהו בסוף שולח בטעות.

האפליקציה מריצה את `main.py` דרך ה-venv הזה בבניית פיתוח, כך שאין שלב אריזה בלולאת העבודה. בבניית שחרור היא מריצה את הבינארי הקפוא.

## אריזה

```bash
.venv/Scripts/python.exe build.py
.venv/Scripts/python.exe test_protocol.py ../app/src-tauri/binaries/pdf2code-engine.exe
```

**השורה השנייה היא העיקר.** אותן 21 בדיקות רצות מול הבינארי הקפוא, וזו הדרך היחידה לדעת שהאריזה לא איבדה משהו. הנימוקים לדגלים ב-`build.py` עצמו; שלושה מהם נושאים משקל:

- **`--onedir` ולא `--onefile`** — onefile מפרק את עצמו לתיקייה זמנית בכל הרצה, מאט את העלייה, ומייצר קובץ שכותב ומריץ עותק של עצמו בכל פעם — בדיוק מה שאנטי-וירוס תוקפני בנוי לשים לב אליו
- **`--collect-all pypdfium2`** — PDFium היא ספרייה נייטיבית. סורק המודולים עוקב אחרי `import`, ו-DLL שנטען בזמן ריצה אינו import. בלי זה המנוע עולה, עונה `ready`, ונופל על המסמך הראשון
- **`--collect-all pdfminer`** — נתוני ה-CMap הם קבצי חבילה. חסרונם אינו מפיל כלום: הוא **משבש טקסט בשקט**, בדיוק במסמכים עם קידודים לא-לטיניים

**נשלח כ-`resources` ולא כ-`externalBin`.** זו הייתה הבחירה הראשונה והיא לא עובדת: `externalBin` נושא קובץ בודד, ובניית `--onedir` היא הרצה פלוס עץ `_internal` של ספריות נייטיביות. הצהרה על התיקייה כולה תחת `bundle.resources` שולחת את הכול ושומרת על המבנה, וצד ה-Rust מאתר אותה מול `resource_dir()`.

**גודל:** 41MB. זה מה שמנוע פייתון עולה, וזה עדיין מביא את ההתקנה כולה לפחות מ-45MB — לעומת ~150MB שאותה אפליקציה ב-Electron הייתה שוקלת לפני שהוספנו מנוע בכלל.

## הפרוטוקול

JSON תחום שורות על `stdin` ו-`stdout`. **בלי HTTP ובלי סוקט** — הנימוק ב-[../architecture.md §2](../architecture.md), והוא עסקי: הלקוח המרכזי קונה אותנו כי שום דבר לא עוזב את המכונה, ופורט מאזין הוא ממצא בסריקת אבטחה שמישהו צריך להסביר.

**בקשה** (Rust ← המנוע), שורה אחת:

```json
{"id":"j7","op":"sleep","args":{"steps":40,"seconds":0.05}}
{"id":"j7","op":"probe","args":{"path":"C:/docs/report.pdf"}}
{"id":"j7","op":"convert","args":{"path":"C:/docs/report.pdf","out":"C:/out","formats":["html","react"]}}
{"id":"j7","op":"cancel"}
```

**על `probe` בנפרד.** הוא פותח מסמך ומדווח מה יש בו — עמודים, תווים, עברית, שמות פונטים — בלי להמיר. שני תפקידים: הממשק צריך מספר עמודים ותשובה ל״האם זה בכלל נפתח״ לפני שהוא מציע להמיר; ו**הוא האופרטור היחיד שנוגע בספריות הנייטיביות.** `echo` ו-`sleep` הם פייתון טהור, ולכן בינארי קפוא שנשלח בלי ה-DLL של PDFium ובלי נתוני ה-CMap **עובר את כל שאר הבדיקות.** `probe` הוא זה שלא.

**על `convert`.** הוא מקבל `out` ומחזיר **שמות קבצים ולא תוכן** — הנימוק בסעיף 4 למטה. `warnings` שומר על הצורה שהממשק כבר מכיר: קוד ופרמטרים, לעולם לא משפט, כי המנוע אינו יודע באיזו שפה קוראים אותו.

ב-`cancel`, ה-`id` הוא **העבודה שמבטלים** ולא הודעה בפני עצמה. אין לו תשובה — שורת הסיום של העבודה המבוטלת היא התשובה, וביטול של עבודה שכבר הסתיימה הוא מרוץ ולא שגיאה.

**תשובות** — אפס או יותר `progress`, ואז בדיוק אחת מ-`result` / `error`:

```json
{"type":"ready","protocol":1,"python":"3.13.5","ops":["compress","convert","echo","edit","exportImages","probe","sleep","text","thumbnails","zip"]}
{"id":"j7","type":"progress","page":12,"pages":40,"phase":"extract"}
{"id":"j7","type":"result","slept":2.0,"steps":40}
{"id":"j7","type":"error","code":"CANCELLED","message":"cancelled"}
```

`phase`, `WarningCode` ומבנה `info` **מועתקים מ-[types.ts](../../src/converter/types.ts) ולא הומצאו מחדש.** הממשק כבר יודע להציג אותם, והמחרוזות המתורגמות כבר קיימות ב-`messages/`.

## ארבעה דברים שנשברים בקלות, ומה מחזיק אותם

**1. `stdout` שייך לפרוטוקול.** `print` אחד ששכחו פולט שורה שאינה JSON. `protocol.claim_stdout()` לוקח את ה-handle האמיתי ומצביע את `sys.stdout` על `stderr`, כך שהטעות הופכת לבלתי אפשרית במקום לאסורה. כל הלוגים ל-`stderr`, והם מגיעים ללוג שלנו ולא לחלון — הם עלולים לצטט מסמך.

**2. קידוד.** תהליך פייתון שעולה על Windows בעברית מקבל cp1255 על הצינורות. התו העברי הראשון שנכתב — שם קובץ, כותרת מסמך, שגיאה שמצטטת אחד מהם — הופך לבייט שהקורא לא יודע לפענח. שלושת הזרמים נכפים ל-UTF-8 עם `newline="\n"`, אחרת Windows מתרגם את תו השורה של המסגור ל-CRLF וה-CR רוכב בתוך השורה. **הבדיקה תפסה את זה בפועל, לא בתיאוריה.**

**3. ביטול חייב להגיע בזמן שהעבודה רצה.** לכן התהליכון הראשי אינו עושה דבר מלבד לקרוא ולנתב, והעבודה קורית בתהליכון נפרד. בלולאה חד-תהליכונית הקריאה הבאה מתרחשת רק אחרי שהעבודה הסתיימה, והביטול הופך לתיאוריה. **נמדד: 7 מילישניות מהבקשה ועד שהעבודה נעצרה.**

**4. הפלט לא עובר בצינור.** ראסטרים של 150 עמודים כ-base64 הם עשרות מגה-בייט.  כותב לדיסק ומחזיר **שמות קבצים**, וזו הסיבה שהוא מקבל  ולא מחזיר תוכן.

**מהירות, שנמדדה ולא שוערה:** 150 עמודים בטקסט בלבד ב-11.7 שניות — 78ms לעמוד. בדיקת ה-QA הקיימת דורשת פחות מ-60 שניות, ולכן אין כאן חסם שמצדיק לחזור לשאלת PyMuPDF.

## הספריות, ולמה דווקא הן

| תפקיד | ספרייה | רישיון |
| --- | --- | --- |
| שכבת ראסטר | pypdfium2 | Apache-2.0 / BSD-3 |
| שכבת טקסט | pdfminer.six | MIT |
| תמונות | Pillow | MIT-CMU |

PyMuPDF עושה את שתי הראשונות לבד, מהר יותר ובפחות קוד, ורישיונה AGPL-3.0 או מסחרי בתשלום. ההכרעה ונימוקה ב-[../decisions.md](../decisions.md).

**אומת מול `fixtures/08-hebrew-doc.pdf`:** pypdfium2 רינדר את עמוד 1, ו-pdfminer.six החזיר 46 תווים עבריים **הנושאים את שמות הפונטים המוטמעים עם תחילית ה-subset שלהם** — `MUFUZY+Alef-Regular`. זה בדיוק הקלט ש-[fonts.ts](../../src/converter/fonts.ts) נכתב לצרוך, כולל הדוגמה שרשומה בהערה שלו.
